# Module descriptor

The canonical ModuleDescriptor may be maintained as `mmp.module.json` or generated from a module definition. The descriptor advertised in discovery MUST correspond to the deployed package. It declares the module ID, publisher claim, package version, MMP version, description, operations and dependency triples.

The Host MUST validate the [descriptor schema](../../schemas/0.1.0/module-descriptor.schema.json), unique tools and triples, exact SemVer for the package and trusted identity/version pins. For a module admitted from a locally pinned package, the advertised `id`, `publisher` and exact `version` MUST equal the trusted pin, and the Host MUST verify the pinned artifact digests and launch paths before it starts the process. A descriptor claim without a matching pin is rejected rather than trusted.

Admission is local to the Host. A module that fails any admission check MUST NOT be registered. The Reference Host admits all pinned packages before it reports readiness and aborts startup on the first failure, so a rejected package cannot leave a partially trusted set. A deployment that admits a module over another transport defines equivalent artifact provenance at its own trust boundary.

The Host MUST enumerate `tools/list` to exhaustion through `nextCursor` and bound the number of pages and entries. For provider admission, it MUST reject repeated cursors, duplicate tool names, reserved `mmp_` names and any tool not declared by the descriptor. Every advertised operation MUST appear exactly once with input and output schemas structurally equal to the trusted catalog entry, and no additional tool may be admitted as a provider operation. The descriptor advertised in discovery MUST describe that same operation set. Ordinary MCP servers without valid extension metadata may be used as ordinary MCP servers under Host policy.

A capability is a case-sensitive ASCII `namespace/name` identifier. Its namespace is controlled by the descriptor publisher or a shared naming authority. Different implementations MAY implement the same triple. Dependencies are exact triples and bind each outbound call. Permission names describe required grants. Effects are `read-only`, `write` or `external`; a Host MUST reject unsupported values.
