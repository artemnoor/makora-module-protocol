# Лаборатория компонуемости MMP

Браузерное приложение запускает отдельные процессы MCP, показывает фактические вызовы и принимает ручное решение после предварительной обработки. Оно использует публичные интерфейсы Reference Host и SDK. Контракты приложения лежат в `contracts/`. Ядро MMP и его спецификация используются без изменений.

## Запуск

Требуются Node.js 22, Python 3.11 или новее и uv. Из корня репозитория:

```sh
npm ci
uv sync --locked
uv sync --locked --project demos/universality/third-party
npm run demo:universality
```

Откройте loopback URL из терминала. Сервер выбирает свободный порт. Можно задать `MMP_PORT` в окружении. Выберите систему, введите задачу, затем заполните форму в панели выполнения. Новый запуск можно создать, пока первый ожидает решения.

- **Исходная** использует TypeScript для метрик, AI для анализа, объединитель с формой A и обработку на выбор человека.
- **Перекомпоновка** использует совместимый Python-модуль метрик, детерминированный анализ, объединитель с формой B и независимо упакованный Python-декоратор. Финализация предшествует нормализации.
- **Без AI** использует правила и алгоритмы. Нормализация исключена из композиции. Финализатор и другие совместимые операции переиспользуются.

По умолчанию `MMP_AI_MODE=fixture` использует воспроизводимые тестовые реализации AI. В режиме `off` обращений к AI нет во всех конфигурациях. Для живого режима задайте `MMP_AI_MODE=live` и ваш ключ в окружении. По умолчанию поддерживается `POLZA_AI_API_KEY` для официального endpoint Polza. Для другого совместимого HTTPS endpoint задайте `MMP_AI_ENDPOINT` и собственный `MMP_AI_KEY`. Модели задаются `MMP_ROUTE_MODEL` и `MMP_WORK_MODEL`. В живом режиме введённые данные передаются выбранному провайдеру.

## Проверки

```sh
npx playwright install chromium
npm run verify:universality
npm run verify:release
```

Для Linux CI можно установить системные зависимости браузера командой `npx playwright install --with-deps chromium`. Автоматический набор использует только контрольный адаптер. Отдельный тест ниже отправляет один синтетический сценарий авторизованному провайдеру, включая вызов двух разных моделей.

```sh
npm run verify:universality:live
```

После изменения доверенного модуля или контракта обновите контрольные суммы командой `npm run build`, затем `node demos/universality/update-pins.mjs`. Перед обновлением проверьте изменения пакета и версию контракта. Контрольные суммы являются локальными пинами оператора.

## Устройство

`harness.mjs` управляет состоянием запуска, источником маршрута, отображением результатов, продолжением и ограниченным повтором. Модель вызывает зарегистрированный `dispatch` через tool calling. Harness проверяет результат и передаёт вызов Reference Host. Модуль распределения уже через Gateway сам вызывает ветви. Объединитель публикует интерфейс как MCP-ресурс. Браузер показывает ресурс в sandboxed iframe.

Встраивание использует объявление `_meta.ui.resourceUri` и чтение `ui://` ресурса с MIME MCP Apps. Для формы выбран короткий локальный мост событий Harness. Полной совместимости с произвольными MCP Apps и их двусторонним API этот пример не заявляет.

Запуски хранятся в памяти 30 минут, привязаны к сессии браузера и недоступны из другой сессии. После перезапуска они исчезают. Отмена прекращает дальнейшие шаги Harness. Результат уже отправленной внешней операции может остаться неизвестным. Stdio создаёт отдельные процессы, а запуск недоверенных пакетов требует отдельной защиты ОС. Эта демонстрация запускает только пинованные локальные пакеты.
